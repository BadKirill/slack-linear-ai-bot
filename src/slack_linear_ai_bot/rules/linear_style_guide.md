# Linear Issue Style Guide

## Title

- Format: `[Area] Verb + object + optional qualifier`.
- Prefer specific product and behavior names.
- Avoid `Fix bug`, `Implement thing`, `Update stuff`, or other generic wording.

## Description

- Put context first in one to three sentences.
- Use Markdown headings for Problem, Expected, Steps, Acceptance Criteria, Evidence, and Links when applicable.
- Write acceptance criteria as `- [ ]` checkboxes.
- Put links at the end and group them by source type.

## Labels

- Use existing labels only.
- Keep label sets consistent across similar work.

## Priority

- 1 Urgent: production incident or blocker.
- 2 High: sprint goal or customer commitment.
- 3 Medium: normal backlog.
- 4 Low: nice-to-have or tech debt.
